# 停机数据处理补充方案

日期：2026-10-04。用户已同意继续处理停机，不补价格、不虚构成交。本文件替代首轮方案中“所有小时必须有实际 K 线、close_time 必须为标准小时末端”的严格假设，其余资金、期间和选参规则保持有效。

## 来源与有限例外

EXP-001 保留失败，不覆盖。追加只读调查已核验 BTC、ETH、SOL 在 2021-12-24、2023-03-24 的六份官方日包及 SHA-256，证据保存于项目 `.cache/halt-source-audit/` 和 `.cache/halt-daily-audit.json`；正式新实验必须复制这些证据和哈希，不能只依赖缓存。

三币 2023-03-24 日包均为 23 条，缺少 13:00 UTC；[币安恢复公告](https://www.binance.com/en/support/announcement/detail/813a31506e9f478ea8c1058b425df87a)明确 14:00 UTC 恢复交易。将 13:00—14:00 标为已核实无行情的停机小时。公告没有提供精确停机起点，12 点小时被截短与停机相关是结合原始数据作出的推断。

非标准 close_time 只接受以下已经逐币核验的精确时间对（UTC）。不得泛化接受任意提前结束时间，也不改变原始值：

| 交易对 | open_time | 原始 close_time |
| --- | --- | --- |
| BTCUSDT | 2021-12-24 04:00 | 2021-12-24 04:59:54.362 |
| ETHUSDT | 2021-12-24 04:00 | 2021-12-24 04:59:56.158 |
| BTCUSDT | 2023-03-24 12:00 | 2023-03-24 12:39:41.646 |
| ETHUSDT | 2023-03-24 12:00 | 2023-03-24 12:39:43.061 |
| SOLUSDT | 2023-03-24 12:00 | 2023-03-24 12:39:46.948 |

标准毫秒或微秒小时末端仍有效。提前结束行保留为实际观察，不推断最后成交以后存在价格或成交；available_time 保守设为下一整点。记录异常结束时间数量与明细。未知 close_time、未知缺口、停机小时内出现实际记录、冲突重复、未收盘、坏 OHLC 一律失败，新增例外需要独立证据和新方法版本。

## 数据表示与样本

- 原始 ZIP 和标准化文件只保留实际记录；质量处理生成连续小时日历。停机行只有 symbol、open_time 和状态信息，行情价格、成交量、trade_count、close_time、available_time、source_id 留空。不得填零价格、前向填价或复制上一根 K 线。
- 新增 market_state=observed/halt、segment_id、history_count、history_ready。停机 history_count=0、history_ready=false；后续 observed 行重新计数。每个连续观察片段隔离指标计算，历史策略信号必须积累 744 条连续已经可获得的观察小时后才允许生成。已核验的提前结束行算观察小时，异常 flag 与原始结束时间保留；不假装恢复了该小时完整交易路径。
- 指标以后按 segment_id 独立计算，禁止 EMA 跳过缺口后接续旧状态。history_ready 是每行 available_time 之后的状态，开盘决策不能使用尚未可获得的同一行状态。744 小时是保守研究默认，不是交易所规则。
- 标签入口到四小时后出口必须在完整五个日历小时中均有真实开盘且没有停机；缺任意小时即剔除。不能压缩时间轴后用“后四条记录”代替“后四小时”。仍执行首轮跨开发／验证／测试边界剔除。
- 提供可复用的成交可用和标签窗口检查函数；本批不实现或声称已经检查了资金账本、指标或模型。
- 分区终点只保留真实开盘及来源、时间和市场状态；其余未来行情与 history_ready 等均掩码。终点是停机时仍保留日历行，但开盘为空，禁止终点成交。

## 后续账本必须遵循的规则

停机没有真实开盘，任何订单都不成交。风险退出请求保留到下一真实开盘，不因策略历史预热而禁止退出；恢复价格跳空仍可能越过 50 USDT 底线。停机持仓净值使用最后已知真实估值并标记陈旧、记录价格年龄，这只属于估值账本，不写回行情，也不视为新收盘风险观察。恢复后使用真实价格更新估值和风控。冷却时间按实际 UTC 时间计算四小时。区间终点无真实开盘时记录未清仓和陈旧估值，不延长区间、不造价格。这些在下一批账本实现时测试。

## 可复现配置与交付

配置新增 data_policy=halt_aware_v1；旧配置无此字段按 strict_v0 读取，复现 EXP-001 的严格失败。版本化日历 JSON 随包分发，记录五组精确异常和三币停机小时、六个来源 SHA。每步源码快照包含 JSON；prepare manifest 和 check-data report 记录该政策文件 SHA，check-data 拒绝政策变化。配置改变登记 EXP-002。

预期日历每币 42,384 小时；已知每币缺一实际小时，因此若没有其他问题实际每币 42,383 条，合计 127,149 实际条目、127,152 日历行。必须按实际读取报告两种数量，停机行不是实际 K 线。分别生成开发、验证、测试的数据分区仅属于质量准备，不做后两区间策略评价。

交付：关键行为检查通过；真实三币 prepare、rules、check-data 全部完成，或如实登记仍然失败的未知异常并保留证据。同步当前文档并说明下一步是共同账本和开发期基准，模型尚未训练。

## EXP-002 后的来源修订：halt_aware_v2

EXP-002 完整核验 264 个归档，但 SOL 标准化失败。全量原始诊断显示仅多一个未预期异常：SOL 2021-12-24 04:00 UTC，月包 close_time=05:00:00.475，跨入下一小时；月包 SHA `e6e88ff1edc3a6910df90bbe311e0ec071913bd8673307adb4d4ecf41db4ef5e`。六份日包调查中的 SOL 对应日包为标准 04:59:59.999，SHA `caa546d9dad68ad8bf9f656ebf6ce86cad9b75d300cc3e5924ba6c0d2d09100f`。该条其余 11 个原始字段完全相同，官方月包／日包存在结束时间差异；不推断原因。

新政策 halt_aware_v2 继承 v1 的停机和五个精确例外，明确 SOL 2021-12 整月使用每日归档，不下载该月月包参与新实验。31 份日包替代一个月包，来源清单区分主动来源选择与 HTTP 404 降级；旧月包及失败证据保留。仍拒绝越界 close_time、未知缺口与冲突，不手工改任何时间或价格。仅一种来源覆盖每个小时，避免把两个冲突版本合并后任意择一。

三币 2023-03-24 12:00 UTC 原始行均 trade_count=volume=quote_volume=0，OHLC 相等且等于 11 点行 close。v2 将这三组精确时间列入 no_trade_bars：原始行与字段保留，market_state=no_trade，不能作为真实成交价格、标签入口／出口或新的估值。该状态来自已核验来源日历，不通过同小时最终成交量动态决定开盘是否下单，也不将它用于模型特征。公告仍未给出精确停机起点，这只表示该归档行不足以支持成交，不声称还原停机精确开始时刻。

这替代 v1 将这三行视为可用观察的约定。质量检查要求这三行存在且无成交、OHLC 相等；若其前一行在本范围内，还核对上一收盘相等，矛盾则失败。history_count/history_ready 在 no_trade 与 halt 行均归零，指标片段在这两种不可用状态处中断；空停机行仍无价格，no_trade 保留原文但不视为新价格。can_execute 在两种状态都 false，标签 08:00→12:00 也必须排除。后续账本估值沿用上一真实价格并标记陈旧，退出保留到下一真实开盘。history 状态只在各行 available_time 后可用；成交可用掩码属于离线执行约束，不能当作在线可提前知道的预测信号。

数量分开：每币预计原始归档行 42,383，含一条 no_trade；可用观察 42,382，另有一个空停机占位；日历合计 42,384。三币预计原始 127,149、可用观察 127,146、no_trade 3、空停机 3、日历 127,152。保留 v1 旧报告的原含义，新报告明确三种数量与状态。

v1 JSON 与 EXP-002 快照冻结保留；v2 单独 JSON、配置 SHA 和新实验 EXP-003。预期日历／观察数量不变，实际归档预计 BTC 88、ETH 88、SOL 118，共 294 个，须以真实运行核对。正式复制六个日包及被排除月包作为诊断证据。记录 v2 政策 SHA，每步 JSON 快照包括 v1/v2 文件。未来基准编号顺延，以登记为准。
